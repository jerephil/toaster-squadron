# Writing voice

Write documentation, code comments, docstrings, changelogs, handoff notes, and release notes in my first-person singular voice: **I**, **my**, and **mine**. Describe my testing, decisions, approvals, and project ownership as my actions; do not narrate them in the third person.

Apply this voice to GitHub release descriptions and documentation inside downloadable packages as well as files in the repo. When updating packaged documentation, refresh its checksum and preserve my tested executable.

Keep legal copyright notices, license text, technical identifiers, and structural comment labels intact. Instructions addressed to readers and factual descriptions of software behavior can remain direct and technical.
